## 二、要解決的問題

同事的觀察：學生做了幾題就沒有動力。網站**外觀**是 RPG，**玩起來**還是考卷：

| 時間點 | 現在學生得到什麼 | 少了什麼 |
|---|---|---|
| 答一題（約 30 秒） | 對錯、+10 EXP | 沒有對手 |
| 過一關（約 5 分鐘） | 結算數字、等級條 | 沒有帶走任何東西 |
| 過一區（約 3 關） | 一枚徽章 | 徽章只能看 |
| 明天 | 沒有事等著他 | 沒有再打開的理由 |

EXP 只給「第一次就答對」，**最需要練的學生拿得最少**。

## 三、順序

| 順序 | 做什麼 | 為什麼排這裡 | 要不要 `?rpg=1` |
|---|---|---|---|
| 1 | **錯題複習** | 不靠美術、不靠登入，舊資料就能用；寵物成長也要靠它 | 不用，直接給全部學生 |
| 2 | **書架分年級** | 改動小；下學期加書之前要先做 | 不用 |
| 3 | **老師進度頁** | 派作業一定要；等 Firebase 設定好就做 | 不用 |
| 4 | **寵物造型**（3 隻給老師看） | 造型要來回修，先定樣子再大量畫 | 預覽頁 |
| 5 | **戰鬥＋寵物樣板**，找一班試玩 | 有效才往下做 | 要 |
| 6 | 其餘寵物、配件、地圖恢復顏色、王城頭目 | 看試玩結果決定 | 要，驗收後才全面開放 |

第 4 項可以和第 3 項同時進行。目標是寒假作業前完成 1～3，日期看學校行事曆。

## 四、錯題複習

### 現在有什麼、沒有什麼
- 現在只有「整關再練一次」，對的題目也要重做。沒有錯題本，也沒有隔天再出現。
- 每題第一次答對或答錯**已經有存**，所以一上線，學生以前的錯題就會出現。

### 規則
1. **哪些題**：第一次答錯的題目（後來重試答對的也算）。
2. **什麼時候出現**：答錯的**隔天**可以練；練對之後，**再過 3 天**出現第二次。
3. **怎樣算學會**：兩次都「一選就對」。錯了就從隔天重新開始。
4. **一次最多 5 題**，約 3～5 分鐘，同一本書的不同關混著出。
5. 選項洗牌、答錯鎖 2 秒、錯兩次看提示，都和現在一樣。
6. **不加 EXP**，不改原本「第一次答對」的紀錄，所以不影響精熟和徽章。
7. 當天也可以馬上訂正（結算畫面「只練剛才錯的」），但不算那兩次，避免背答案位置。

### 畫面
- 首頁每本書的封面顯示「今天可以複習 4 題」。
- 地圖上方一個「錯題複習」按鈕，裡面分三格：今天可以練、還沒到時間、已經學會。
- 沒有錯題時顯示「目前沒有要複習的題目」。

### 技術
- 每題多存一欄：練對幾次、上次練的時間。兩台裝置合併時，以**時間比較新的**為準，補 `save-test.mjs` 的測試。
- `engine.js` 加一種「從不同關挑題」的闖關，補 `engine-test.mjs` 的測試。
- 紀錄是跟著「第幾關第幾題」，以後如果把題目換成完全不同的題，那題的錯題紀錄要一併清掉。

## 五、書架

原本 15 本排在一起，下學期加 15 本就是 30 本，**會太擠**。老師決定收成三款教材，下學期變六款：

```
   首頁：   [ 六上教材 ]   [ 五上教材 ]   [ 四上教材 ]
   點進去：  國語   數學   英語   自然   社會
```

- 首頁標出「上次打開」的教材；封面顯示過了幾關、今天可以複習幾題。
- 教材清單寫在 `js/books.js` 的 `SHELVES`，下學期加三筆就好。
- 每一本書、每一區原本的網址不變，已經貼出去的連結不會壞；學生的進度也不受影響。
- 開站速度不變，因為本來就是點進去才下載那本書。

**三年級**：建議這學期先不做。電腦操作還不熟、下學期才學 Google 帳號，沒有登入就沒有紀錄；家長也有疑慮。書架分年級後，之後要加只是多一個按鈕。

## 六、寵物

### 設計方向：台灣原生動物
- 學生認得、和自然社會課本相關，也不會像任何現成的遊戲角色。
- **先少而精**：3 隻起始寵物＋每本書 1 隻，共 18 隻。不做一關一隻或一區一隻。

### 造型規則（避免畫得奇怪）
1. 兩頭身、圓形為主，**頭和身體都是簡單圓形**，臉頰不外凸。
2. 眼睛用圓點加一個亮點，不用大虹膜；表情溫和，不露牙齒。
3. 不穿衣服、不拿東西。每隻只有**一個**最容易認的特徵。
4. 一隻最多 3 種主色，和地圖一樣有深色描邊。
5. 遮住細節只看剪影，也認得出是什麼動物。
6. 長大只是體型變大、特徵更明顯，不變成另一種動物。
7. **每一隻先給老師看正面、側面和縮小到 40 px 的樣子，同意了才放進遊戲。**

### 第一批：三隻起始寵物

| 寵物 | 一眼認得的特徵 | 主色 | 個性 |
|---|---|---|---|
| 小黑熊 | 胸前 V 字白紋 | 深灰、白 | 穩重 |
| 藍鵲寶寶 | 長尾巴、紅嘴 | 藍、黑、紅 | 活潑 |
| 小穿山甲 | 背上一片片鱗甲，會捲成球 | 棕、米 | 害羞 |

剪影分別是圓的、有尾羽的、有鱗片的，不會混淆。避開貓和兔，因為主角已經是貓和兔。之後的候選：梅花鹿、領角鴞、黑面琵鷺、水獺、獼猴、帝雉、石虎、櫻花鉤吻鮭、樹蛙、綠蠵龜。

### 怎麼拿到
| 時間 | 得到 |
|---|---|
| 第一次進站 | 選完角色，三顆蛋選一顆 |
| 過第一關（約 5 分鐘） | 蛋孵化 |
| 每本書完成第一區（平均約 3 關） | 這本書的寵物 |
| 之後每完成一區 | 這一區主題的配件（帽子、圍巾、背飾） |

### 怎麼長大
- 分寶寶、少年、成年。成長看**星光**，不看 EXP，訂正和複習也算。
- 少年約 150 星光（約兩區），成年約 400 星光（約一本書）。數字等試玩再調。
- 可以隨時換帶哪一隻，沒帶的不會退步。
- **不會餓、不會生病、不會離開**，放假沒開也沒有損失。
- 名字從清單選，不開放自己打字，避免出現不雅的名字。
- 給什麼寵物事先講清楚，不用抽的。

### 需要老師提供的（不一定要）
1. 三、五張「覺得可愛」的圖，再加一兩張「不要像這樣」的圖，最有幫助。只用來抓感覺，不會照畫。
2. 可以讓幾個學生從候選動物裡投票。
3. 圖放在 `private/寵物參考/`，不要放進公開的資料夾，也不會上傳。

沒有參考圖也可以開始，我先照上面的規則畫第一批三隻。

## 七、答題就是戰鬥（`?rpg=1`）

> 王國被「迷霧」罩住，迷霧怪擋在路上。每解開一道題，就吹散一點霧。

答題畫面上方加一條戰鬥區，題目區版面不變：

```
┌──────────────────────────────────────┐
│ 離開   質數礦坑・第 1 關      70 EXP │
│   貓劍士＋小黑熊          迷霧怪     │
│   連擊 3                  霧 ■■■■□□□ │
├──────────────────────────────────────┤
│  第 5 題 …                           │
└──────────────────────────────────────┘
```

| 現有規則（不改） | 戰鬥裡的樣子 |
|---|---|
| 一關 7 題 | 7 層霧，答對一題散一層 |
| 第一次就答對 +10 EXP | 強力一擊，連擊加 1 |
| 重試才答對 | 普通攻擊，一樣散一層 |
| 答錯鎖 2 秒 | 怪縮進霧裡 2 秒，角色不受傷 |
| 錯兩次要看提示 | 寵物說「先看看這個線索」 |
| 7 題都答對＝過關 | 霧散了，怪高興的離開 |
| 精熟 | 這一關的石台變金色 |
| 錯題複習 | 「回頭霧」，小隻的迷霧怪 |

- 迷霧怪只做 6 種，用顏色區分；收集的對象是寵物，不是怪。
- 不會死、不會輸。連擊只有畫面效果，不加分。
- 長題目往下捲時，戰鬥區收成細條；英語聽力播放時停動畫。

## 八、星光與等級

| 做到的事 | 星光 |
|---|---|
| 第一次就答對一題 | 2 |
| 重試後答對一題 | 1 |
| 一題錯題複習到「學會」 | 2 |
| 一關精熟 | 5 |
| 拿到一枚徽章 | 20 |

- 同一題不能重刷。星光由作答紀錄直接算出來，所以以前的進度一上線就有。
- 星光只讓寵物長大，**不換任何答題優勢**。先不做商店。
- 等級照現在的做法，之後可以解鎖新角色。

**不做的**：音效、抽卡、排行榜、學生對打、連續登入中斷懲罰、限時絕版。

## 九、老師進度頁

照 3D 校園 `teacher.html` 的做法：老師登入 → 選 Classroom 課程 → 看每位學生。

- 看得到：每本書過幾關、精熟幾關、哪一天過關、錯題還剩幾題、全班最多人錯的題目。
- 可以選「哪幾區、到哪一天為止」，列出誰完成、誰還沒。
- 建議「過關」算完成，「精熟」算加分。在家無法確認是不是本人作答，不建議當正式成績。
- 派作業：把那一區的網址貼到 Classroom 就好，不另外做派作業功能。

### 老師要在學校設定的
專案是 `xikou-studio-83723`，和 3D 校園那個分開，所以要再做一次：

1. Google Cloud 控制台 → API 和服務 → 程式庫 → 啟用 **Google Classroom API**。
2. OAuth 同意畫面（新版叫 Google Auth Platform →「資料存取權」）→ 新增三個範圍：`classroom.courses.readonly`、`classroom.rosters.readonly`、`classroom.profile.emails`。
3. API 和服務 → 憑證，複製網頁用戶端的「用戶端 ID」。
4. admin.google.com → 安全性 → 存取權與資料控管 → API 控制項 → 管理第三方應用程式存取權 → 貼上用戶端 ID → 設為「信任」。**老師和學生兩個網域都要各做一次。**
5. 用一個真的學生帳號登入練功王國，測一次換裝置進度還在不在。

第 6 步等進度頁做好才有：把新的 `firestore.rules` 貼到 Firebase 控制台發布（老師帳號可以唯讀學生進度）。完整圖文說明見 3D 校園的 `docs/Firestore第二階段設定說明.md`。

## 十、技術上要注意

- **開關**：`?rpg=1` 才載入 `battle.js`、`rpg.js`，沒有開關時現在的畫面和程式不變。開工前先做還原點。
- **試玩資料**：RPG 的新資料（選了哪隻寵物、配件）在試玩期間只存這台裝置，不寫進雲端進度。錯題複習是正式功能，會寫進雲端。
- **存檔合併**：`merge()` 只逐項合併 `books`，其他欄位是一邊蓋掉另一邊，新欄位要補合併規則和測試。
- **效能**：答題時 3D 地圖是停住的，所以怪和寵物先用 `render-sprites.mjs` 畫成圖，動作用 CSS。寵物 18 隻 × 3 階段約 1 MB，用到才下載。
- 平面地圖模式、「減少動態效果」的裝置都要能玩。

## 十一、怎麼知道有沒有效

同一班、同樣 15 分鐘，開關打開前後各試一次，記三件事：平均做完幾題、幾個人做滿 15 分鐘、第一次答對的比例有沒有下降。最後一項下降，代表學生趕著打怪沒看題，要調慢節奏。
