# 答題畫面四項修正（2026-11-21，Muse 試玩四上數學時找到）

這四個問題是整站共用的程式，每本書都會一起變好；題目內容一題都沒改。

## 1. 答對後，題目的圖被捲出畫面
- **原因**：答對後程式會自動把「詳解」整段捲進畫面（`js/ui.js`）。詳解很長、手機畫面又小，就會往下捲很多，圖的上半部被捲到最上面那條（離開、寶石、EXP 那一列，它固定在畫面頂端）底下，看起來像圖只剩一半。
- **改法**：只有在詳解完全看不到時才往下捲，而且只捲到「詳解的開頭露出來」為止；如果再捲就會把圖蓋住，就停在圖的頂端，剩下的讓學生自己往下滑。打開提示時的自動捲動也照同樣規則。
- **五上數學「縱軸 0–65 變 0–25」**：查了紀錄，那張圖（`data/fig/mn5-01-a.svg`，資源回收疊加長條圖）從 11/16 做好到現在都沒改過，縱軸一直是 0 到 65。所以當時看到「只到 25」，應該就是這個捲動把圖的上半部蓋住造成的誤判，圖本身沒有錯。

## 2.「同一題錯兩次要先看提示」各書不一樣
- **原因**：不是資料檔不同，也沒有分書的程式，每本書用的都是同一條規則。舊規則是「錯 2 次時，這題要看過 1 段提示」——如果學生在答錯之前就先看過提示，錯第 2 次時已經「看過 1 段」，就不會被擋。所以 Muse 有時候被擋、有時候沒被擋，看起來像三種做法。
- **改法**：改成「錯第 2 次起，每錯一次都要再打開一段**新的**提示才能再選」，答錯前先看的不算；3 段提示都打開了就不再擋（沒有新的可以看）。這就是說明頁寫的「同一題錯兩次，要先看提示才能再選」。規則測試加了這種情況，`node tools/engine-test.mjs` 全部通過。

## 3. 地圖頁首的 EXP 是全部的書加起來
- **原因**：頁首的 EXP 一直是把所有書加總；書架書卡和答題畫面顯示的則是這本書的。紀錄裡沒有寫「要跨書累計」的設計，是兩個地方沒對齊。
- **改法**：進到某一本書（地圖、關卡說明）時，頁首只顯示這本書的 EXP，和書卡一樣；回到首頁才顯示全部加起來。旁邊的徽章數不變（按下去打開的是整本徽章冊，列的是每本書）。沒有動到存檔，存檔測試照樣通過。

## 4. 重練時題目順序都一樣
- **原因**：本來就沒有任何一本書會打亂題目順序（每次打亂的是四個選項）。看起來「有的書會換順序」，是因為沒過完的關會從還沒答對的那題接著做。
- **改法**：第一次闖關照原本的順序（由淺到深、第 6、7 題是素養題）；已經過關的關「再練一次」時，七題的順序每次重新打亂，上面的「第幾題」和寶石也照打亂後的順序排。關卡說明會寫「再練一次時題目順序會打亂」。
- 檢查過：沒有題目寫「承上題」，打亂順序不會讓題目看不懂。

## 試過的地方
- 本機 `http://127.0.0.1:5181`，手機寬度 375px 和電腦寬度都試過：四上數學長條圖題答對後，圖完整留在畫面裡；五上自然先看提示再錯兩次，會被擋到再看一段新的提示；同一關再練三次，三次題目順序都不同；五上自然地圖頁首 0 EXP、四上數學地圖頁首只顯示四上的 EXP、首頁顯示加總。
- 還沒在真的 Android 手機上試，推上去後請在線上看一次。
