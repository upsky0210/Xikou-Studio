# 網站審核與分工計畫（2026-11-12）

審核範圍：全部程式（`js/`、`sw.js`、`firestore.rules`）、五本書的題庫資料、手機尺寸實際操作一輪（登入畫面 → 首頁 → 地圖 → 區域 → 答題 → 結算）。
沒有審到的：真的 iPad、真的學校帳號登入、兩台裝置同時使用（這三項只能看程式推斷，下面會標「未實測」）。

## 一、沒問題的部分

- 手機尺寸（375×812）操作一輪，主控台沒有任何錯誤；沒有左右捲動；按鈕都在 44px 以上。
- 五本書 66 關、462 題，格式檢查全部通過：每關 7 題、沒有重複選項、沒有重複題目。
- 題目文字顯示前都有跳脫，沒有看到可以塞進惡意內容的地方。
- 資料庫規則只准學校帳號讀寫自己那一份，其他一律擋掉。

## 三、分工：哪個模型做哪些事

原則：會動到學生資料、要做設計判斷的給最強的模型；有明確規格的例行修改給便宜的。價格比例（API 定價）Fable：Opus：Sonnet 約 4：2：1，Haiku 再便宜很多。

| 模型 | 適合的工作 | 這次分到的項目 |
|---|---|---|
| **Fable 5.2**（最強） | 出錯會掉資料的程式、要設計規則的事、最後把關 | A1 存檔合併、A2 iPad 登入改法、B1 防亂點規則的設計與實作、老師進度頁的設計和資料庫規則、每一批改完後的程式審查 |
| **Opus 5.5** | 需要學科判斷的題目內容、中等難度的程式 | B3 重寫社會干擾項、B2 對照教師用書預審 51 關草稿、B4 寫總複習關、英語老師後續回饋的修題、A3、A4、B5 |
| **Sonnet 5.5** | 規格清楚的例行修改 | C1 service worker、C2、C3、C6 小修、C4 測試和自動檢查、C5 更新 README |
| **Haiku 5.5** | 純跑工具、整理清單 | 每次改題後跑組裝和檢查、產生抽驗清單、列出正解偏長的題目給 Opus 改 |

注意：寫題和審題不要用同一個模型同一次對話做完，審的那一輪另外開一個對話，才看得出問題。
